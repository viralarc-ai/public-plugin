# 客戶名單：收錄、判斷、追蹤與匯出

## 使用者在介面中的操作

進入「客戶名單」，以名稱、選填的表情符號及說明建立名單，再選取名單。使用者
可手動新增資料列、直接修改名稱與分數、變更狀態和標籤、編寫備註、依狀態
篩選，以及選取資料列刪除。開啟項目後可查看原始貼文、備註與活動時間軸。

「名單偏好設定」分成以下頁籤：

| 頁籤 | 設定 |
| --- | --- |
| 顯示欄位 | 顯示、隱藏與排列欄位。 |
| 狀態 | 狀態名稱、顏色、預設狀態，以及是否計入彙整統計。 |
| 標籤 | 可用標籤與預設值。 |
| 分享 | 啟用、複製或開啟公開連結；符合資格的組織使用者可設定組織檢視或編輯權限。 |

使用者也能從海巡結果、回覆紀錄、貼文留言者與提及專案收錄對象，保留各自的
來源與互動脈絡。有價值的搜尋結果可以直接收錄，不需要先發送回覆。

## ChatGPT 工作流程

1. 以 `list_lead_lists` 與 `get_lead_list` 確認目標名單與選項。建立名單使用
   `create_lead_list`。讀取相關的 `list_lead_list_entries` 分頁後，才能聲稱
   完整掌握名單或挑選資料列。
2. 依來源選用收錄操作：

| 來源 | 工具與所需脈絡 |
| --- | --- |
| 社群帳號 | `add_lead_list_entry`，提供實際平台與帳號名稱。 |
| 海巡或輿情搜尋回傳的貼文 | `add_topic_result_to_lead_list`，提供名單、自有專案、帳號、實際貼文與原因。 |
| 選定的回覆紀錄 | `import_reply_history_to_lead_list`，將符合資格的 `threads_auto_reply_log_id` 傳入 `replyHistoryIds`；待審草稿 ID 不是回覆紀錄 ID。 |
| 自有貼文的留言者 | `start_comment_export`，指定帳號、貼文、平台與 `includeNested` 選擇。 |
| 已審核的專案提及 | `capture_mention_lead`，提供目前專案項目的版本與內容指紋。 |

3. 用 `get_lead_list_entry_timeline` 了解先前來源與互動。透過
   `update_lead_list_entry` 修改支援的顯示名稱、分數、狀態、標籤與備註。
   使用實際選項 ID；省略的值維持原樣，明確的空值或 null 則可能清除欄位。
4. 用 `update_lead_list` 修改支援的名稱、說明、狀態或標籤定義、預設值及
   顯示欄位。保留既有 ID 與仍被項目使用的選項。介面中的組織分享權限及
   狀態是否計入統計，並未開放為這些工具的參數。
5. 公開分享使用獨立的 `set_lead_list_public_sharing`，須符合使用者公開存取
   的意圖。刪除選定資料列用 `delete_lead_list_entries`；確定要刪除整份名單
   才使用 `delete_lead_list`，關聯專案等服務檢查可能阻止刪除。
6. 用 `export_lead_list_csv` 取得下載連結。匯出與留言匯入工作不同。匯入以
   `get_comment_export` 查詢；用 `cancel_comment_export` 取消時，已匯入
   項目仍會保留。

貼文可以是銷售跟進、客服處理或輿情追蹤的依據，應以實際內容說明收錄原因。
可編輯分數與畫面上的 AI 公關危機標記是不同欄位；沒有確認結果時，不要聲稱
手動收錄已設定危機標記。

範例：「把這些搜尋結果加入租客名單，替符合條件的人加標籤、註明收錄原因，
再給我 CSV 下載連結。」
