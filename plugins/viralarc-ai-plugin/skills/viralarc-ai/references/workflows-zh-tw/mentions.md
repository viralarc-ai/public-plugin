# 提及：篩選檢視、審核、回覆與收錄

## 使用者在介面中的操作

選擇 Threads 帳號，進入「提及」。「全部提及」是內建檢視；使用者可建立自訂
提及專案，套用不同規則。進入或重新整理時，先同步帳號提及，再處理自訂專案
規則。專案分頁區分待處理、待審核及已處理項目。

| 專案設定 | 用途 |
| --- | --- |
| 名稱 | 自訂檢視的名稱。 |
| 提及類型 | 主貼文、直接回覆、巢狀回覆或深度不明的回覆。 |
| 媒體類型 | 文字、圖片、影片、輪播或未知類型。 |
| 關鍵字 | 比對提及本文或主貼文；可用包含、完全相符或正規表示式，設定全部、任一、排除字詞及大小寫。 |
| 發布時間 | 開始與結束範圍。 |
| 連結客戶名單 | 明確收錄時的目標名單；只連結不會加入任何人。 |
| 安全回覆 | 轉往原生瀏覽器編輯器，由使用者操作，不直接透過 API 發送。 |

回覆設定側面板可儲存具名稱的回覆選項、相對權重、文字或媒體，以及關聯名單
的標籤。純文字選項可搭配另一組具有權重的隨機圖片。準備回覆不會發送，
也不會套用標籤。

## ChatGPT 工作流程

1. 用 `list_mentions` / `get_mention` 讀取已同步的帳號資料。使用者要求載入
   最近或較早資料時，才呼叫 `sync_mentions`，下一頁沿用回傳游標。讀取本身
   不代表要求同步。
2. 用 `create_mention_project` 或 `update_mention_project` 設定篩選條件。
   修改前先用 `get_project` 讀取目前規則版本。「全部提及」是虛擬檢視，
   不可當成專案建立或刪除。
3. 同步後需要評估時，呼叫 `process_mention_project`。以
   `list_mention_project_entries` 與 `get_mention_project_entry` 查進度及
   各項結果，不要為了檢查而重複啟動工作。
4. 審核使用 `review_mention`，提供 approved/rejected、目前的
   `rulesRevision` 與 `contentFingerprint`。審核不會發送或收錄。要儲存作者
   時，使用 `capture_mention_lead` 加入關聯名單，並可指定實際狀態、標籤 ID。
   收錄與回覆分開處理。
5. 範本使用 `update_mention_reply_settings`，提供目前回覆版本。省略
   `randomImages` 保留圖片池，空陣列則清除。`prepare_mention_reply` 必須
   在明確內容、範本選項或隨機選取中擇一；範本與隨機選取須提供
   `configRevision`。重試時沿用已選定草稿，不要重新抽選。
6. 明確要求發送時使用 `send_mention_reply`。安全回覆會回傳待使用者點擊
   的轉交操作，一般發送也可能進入排程，兩者都不等於已發布。結果不明時
   使用 `reconcile_mention_reply`；已有實際回覆可用 `link_mention_reply`
   交由服務確認歸屬與目標。

只有使用者明確確認未發送，才使用 `confirm_mention_reply_unsent`。手動確認
「已回覆」須符合服務端條件：轉交至少十分鐘後，成功查核仍未找到回覆。
不可虛構發布紀錄。`undo_mention_reply_confirmation` 只撤銷手動確認。
實際回覆或名單收錄紀錄可完成處理；正在排程或轉往編輯器本身不算完成。

範例：「整理 Threads 上提到配送延遲的貼文，排除我們自己的廣告，把審核通過
的作者加入客服名單，並準備回覆讓我確認。」
