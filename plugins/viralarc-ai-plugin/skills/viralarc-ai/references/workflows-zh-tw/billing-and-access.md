# 訂閱管理、點數、權限與支援

## 使用者如何使用設定

「設定」區分一般、訂閱管理、付款紀錄、方案權限、社群連結、已連接應用程式、
外部存取、合約與支援。訂閱管理顯示目前方案、續訂或試用狀態、預定方案變更
及取消控制。取消訂閱需填寫原因，與取消預定方案變更是不同操作。方案選擇與
結帳在訂閱視窗進行，帳戶加值則使用付款結帳。付款及訂閱決策應在這些介面
完成。

## ChatGPT 工作流程

1. 用 `get_billing_summary` 讀取訂閱、實際生效的方案或權限與剩餘點數。
   加購點數與一般點數餘額不同，保留缺漏或無法取得的欄位及實際方案 ID。
2. 查詢功能是否可用時，同時檢查所選帳號的 `get_automation_capabilities`。
   連接問題、服務提供者不支援、方案限制與點數不足，需要不同處理方式。
3. 用 `list_payment_history` 讀取成功付款。`amount_cents` 是該貨幣的最小
   單位金額，不是發票清單、退款紀錄、失敗付款或完整點數帳本。
4. 購買、加值、變更或取消方案、發票及合約管理，應引導使用者到對應設定或
   結帳介面。此 MCP 工具集沒有帳務寫入操作，不要聲稱已付款或變更訂閱。
5. 產品操作說明可使用 `listSupportDocuments` 與 `getSupportDocument`。
   解釋回傳的功能錯誤與下一步；缺漏付款紀錄或尚未解決的服務問題，應導向
   支援，不要猜原因或承諾升級一定能解決。

OAuth 的 `mcp:all` 允許代表使用者操作原本可用的工具，仍受資料所有權、方案、
服務提供者與點數限制，不會提供管理員權限。不要要求使用者在對話貼上付款
資料、登入權杖、平台密鑰或更新權杖。

範例：「查看我的方案、剩餘點數及最近三筆成功付款，再說明這個 Instagram
帳號能不能使用連結追蹤。」
