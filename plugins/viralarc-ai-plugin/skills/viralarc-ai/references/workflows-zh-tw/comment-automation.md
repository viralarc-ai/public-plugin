# 留言自動化與留言轉私訊

## 使用者如何設定

在「貼文管理」選取自己的貼文。「批次回覆」處理選定的既有留言；「自動回覆」
或「自動回覆與私訊」設定未來留言的處理方式。即使介面在同一流程提供兩者，
建立自動化與發送給既有留言仍是不同選擇。

### Threads

「批量生成」依各則留言產生 AI 回覆；「統一回覆」使用固定內容。設定提示或
回覆內容、介面支援的關鍵字條件，以及目標客戶名單。編輯器可帶入帳號的品牌
資料。立即批次處理前，先檢視並選取符合條件的留言；持續處理則儲存機器人。
既有機器人可修改或暫停。

### Instagram 與 Facebook

設定流程將下列選擇分開：

| 設定 | 要確認的內容 |
| --- | --- |
| 觸發條件 | 所有留言或指定關鍵字。 |
| 公開回覆 | 是否在貼文下回覆，並設定一組或多組回覆範本。 |
| 私訊 | 是否發送私訊，並設定文字及選填的連結、按鈕標籤。 |
| 連結追蹤 | 追蹤設定好的私訊連結；編輯時保留既有連結身分。 |
| 客戶名單 | 要收錄留言者的目標名單。 |
| 自動化 | 是否處理未來留言。 |
| 既有留言 | 是否立即發送，以及選中的確切留言。 |
| Instagram 追蹤後解鎖 | 在支援時，設定初始訊息、確認方式或關鍵字，以及尚未追蹤時的訊息。 |

Instagram 追蹤後解鎖需要受支援的 Zernio 連接方式。提供選項前先確認帳號
能力；原生帳號不會自動改走 Zernio。介面保留舊版後續訊息設定，但自動發送
後續訊息尚無實作，不要承諾可用；手動批次會拒絕 `followUp: true`。

## ChatGPT 工作流程

1. 確認帳號與自有貼文。使用者要挑選批次對象時，用 `get_post_comments`
   檢視留言。設定前先讀取 `get_automation_capabilities`，並以 `get_project`
   讀取既有專案。
2. 未來留言使用 `create_comment_automation`，提供對應平台的設定。修改時
   優先使用 `update_comment_automation` 的 `patch`，並保留原有 `platform`。
   未指定的公開回覆、私訊、連結、範本及追蹤後解鎖設定應維持原樣。完整的
   `configuration` 是整份編輯器輸入；不要同時提供兩種形式。
3. 既有留言批次使用 `reply_to_existing_post_comments`，提供已檢視的
   `commentIds` 與該頁的 `after` 游標。只在使用者要求的範圍內，以
   `nextCursor` 繼續處理。Threads AI 生成可能回傳待審草稿，不要當作已發送。
4. 單一留言改用 `reply_to_post_comment`。依實際結果回報公開回覆、私訊、
   跳過的重複項目與失敗項目。追蹤後解鎖的中間私訊步驟，不代表最終連結
   已送達。
5. 持續執行使用 `pause_comment_automation` 或 `resume_comment_automation`。
   複製設定到自有帳號或貼文時，使用 `copy_comment_automation`；只有確定要
   取代既有設定，才提供 `replaceProjectId`。複製後的追蹤連結與原專案不同。

有歧義時，先確認觸發條件、公開回覆、私訊、目標名單，以及會影響目前留言、
未來留言或兩者。留言者匯入與 CSV 下載請見[客戶名單](lead-lists.md)。

範例：「這篇 Instagram 貼文有人留言 GUIDE 時，私訊指南給他，公開回覆簡短
一點，追蹤連結並加入指南名單。套用到未來留言及這五則既有留言。」
