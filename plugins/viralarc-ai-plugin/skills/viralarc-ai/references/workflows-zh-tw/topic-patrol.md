# 工作流程一：一般海巡 — 找到機會並參與互動

## 在 ViralArc 中如何設定

進入「海巡大師」、選擇社群帳號，再新增或編輯海巡主題。編輯器會收集要找的
貼文類型、「我找貼文的目的 / 想要留的言是」及「你的角色」。「進階規則」可
加入排除條件或不同情境的回覆指示。手動海巡可搜尋、檢視結果、產生回覆、
修改內容，再逐則發送。

| 設定 | 在對話中要確認的內容 |
| --- | --- |
| 海巡主題與搜尋關鍵字 | 目標對象、情境與實際搜尋詞。臨時搜尋每次最多提供五組關鍵字。 |
| 留言目的與角色 | 回覆目標、品牌語氣，以及代表的身分。 |
| 進階規則 | 哪些貼文應排除，哪些情境應採不同的回覆方向。 |
| 創建自動化專案 | 是否交由 ViralArc 背景執行。由 ChatGPT 負責執行時應關閉。 |
| 發送模式 | 全自動發送、經人工審核或不留言；與是否定期執行分開設定。 |
| 每日回覆上限 | 使用者要求的上限，須符合支援的 1–40 則範圍與帳號限制。 |
| 搜尋時間範圍 | 要搜尋多久以前的貼文，保留使用者指定的時間範圍。 |
| LINE 通知整合 | 海巡結果摘要與高度相關結果是不同的通知選項；先在社群連結中連接 LINE。 |
| 自動加入客戶名單 | 收錄到哪份名單，以及判斷是否值得收錄的原因；不必先發送回覆。 |

使用 `create_topic_tracking` 或 `update_topic_tracking` 儲存設定，修改前先
讀取現有內容。建立專案本身不會啟動 ChatGPT 排程。接手定期工作時，另讀
[統籌執行與操作恢復](orchestration.md)。

## ChatGPT 工作流程

目標是找到值得互動、且能達成使用者目的的貼文，例如協助潛在客戶、提供相關
服務，或參與有價值的討論。一般海巡可以先準備回覆草稿供人工審核，也可以
依使用者的明確指示發送回覆。

1. **確認搜尋與互動目的。** 釐清要找哪類貼文、使用者代表的身分、希望透過
   回覆達成的目標，以及應排除的情況。有適用的品牌資料時，先沿用其內容。
   臨時搜尋不一定要建立專案。
2. **一次完成搜尋與篩選。** 呼叫 `search_threads_posts`，提供 `keywords` 與
   `criteria`。篩選條件包含 `topic`、`requirements`，以及選填的 `persona`
   與 `advancedRules`。也可以提供 `projectId` 沿用已儲存的設定，或使用
   `search_topic_tracking_now` 執行既有專案的關鍵字與設定。搜尋會使用既有
   點數，不會發送回覆。
3. **閱讀實際搜尋結果。** 以回傳的 `executionId` 呼叫
   `get_threads_search_results`，分頁閱讀保留的結果。說明哪些貼文符合需求，
   並保留原文與連結。相關性分數 0、1、2 表示是否適合這次互動，不代表情緒
   或公關危機的嚴重程度。需要調整篩選時，對快照中的貼文 ID 使用
   `filter_threads_posts`，不必重新執行付費搜尋。結果有截斷或僅涵蓋部分
   資料時，應清楚說明。
4. **將有價值的結果加入客戶名單。** 結果回來後，使用 `list_lead_lists` 選擇
   使用者指定的客戶名單，或透過 `create_lead_list` 建立。若要保留貼文來源，
   呼叫 `add_topic_result_to_lead_list`，提供 `leadListId`、`accountId`、
   關聯且屬於使用者的 `projectId`、實際的 `postId`，以及簡短的收錄原因
   `reason`。這會保留作者與原始貼文脈絡，不需要先發送回覆。臨時搜尋也要
   保留這些脈絡時，先建立已暫停的海巡專案。若只需要加入社群帳號，則可
   使用 `add_lead_list_entry`，不必建立專案。
5. **依要求撰寫與發送回覆。** 對已通過篩選且有關聯專案的結果，使用
   `prepare_topic_reply` 產生或儲存待審草稿，再於使用者要求發送時呼叫
   `send_topic_reply`。若要直接回覆某則實際貼文，可使用
   `reply_to_threads_post`，不必有已儲存的專案。ChatGPT 可在對話中呈現及
   修改回覆。既有的持續發送指示只能在其授權範圍內套用；搜尋或收錄客戶
   名單本身不代表可以發送回覆。
6. **回報本次處理結果。** 說明選中了哪些貼文、哪些作者已加入客戶名單，
   以及回覆目前是草稿、已發送、正在排程，或結果尚未確認。使用操作回傳
   紀錄與 `get_agent_action_status` 查明結果不確定的操作，再決定是否重試。
   排程執行時，依相同步驟處理，並遵守已設定的預算與互動規則。

範例要求：「用海巡大師找 Threads 上最近在台北求租的貼文，排除房仲廣告和
已經找到房子的人。把有價值的結果加入我的租客名單，並準備實用的回覆讓我
審核。」
