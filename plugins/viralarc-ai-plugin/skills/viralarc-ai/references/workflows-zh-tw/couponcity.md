# 酷碰城市：優惠券、渠道與核銷

## 使用者在介面上的操作

開啟「酷碰城市」，選擇優惠券或新增一張，不需要先連結社群帳號。
「優惠券內容」可設定標題、說明、使用條款、領取對象、領取期間、領取後效期、
等待天數、統一截止時間及可核銷項目。「樣式」可調整顏色、字型及上傳圖片。
「分享與成效」提供已發布的 Shortlink 連結、渠道追蹤碼及點擊、領取、核銷統計。
擁有者可在「工作人員權限」管理人員。核銷頁可掃描 QR code 或貼上顧客提供的核銷碼。

必須區分尚未儲存的編輯內容、帶有版本編號的已儲存草稿，以及不可變更的已發布版本。
儲存草稿不等於發布；重新發布只會讓後續領取者看到新內容，已領取者保留原本版本、
可核銷項目及效期。停止領取後，已領取的優惠券仍可在效期內核銷。

## 優惠券流程

1. 使用 `list_coupons` 並依游標讀完需要的頁面，再選擇有權限的優惠券。
   用 `get_coupon` 分別讀取已儲存草稿、版本編號與已發布內容。
   需要品牌背景時，可使用現有品牌資料工具。
2. 用 `create_coupon_draft` 建立草稿，或用 `update_coupon_draft` 儲存完整的預期內容。
   保留既有項目 ID、無關設定及圖片。圖片上傳與移除仍使用原生介面，不可捏造儲存路徑。
   若內建編輯器有未儲存內容，請使用者先在介面儲存或放棄，再直接修改已儲存狀態。
3. 使用 IANA 時區及 UTC ISO 日期時間。登入會員每張券可領取一次；不需登入的重複領取模式
   會產生各自只能核銷一次的領取紀錄，且等待天數必須為零。效期自領取時計算，可能被
   統一截止時間縮短；首次有人領取後，統一截止時間即鎖定。
4. 僅在使用者要求時呼叫 `publish_coupon` 發布或重新發布，帶入最新版本編號與預期內容，
   成功後回傳伺服器提供的 Shortlink 連結。明確要求停止領取時，使用 `close_coupon`。

版本衝突時重新讀取，不能覆蓋較新的內容。此流程沒有提供刪除或封存工具，不可自行宣稱完成。

## 渠道、人員與成效

- 擁有者可用 `list_coupon_tracking_codes`、`create_coupon_tracking_code`、
  `rename_coupon_tracking_code` 管理既有已發布優惠券的渠道碼。使用回傳的追蹤連結；
  重新命名不會改變碼本身或目的地。
- 使用者明確要求時，可以將追蹤連結用於社群回覆、留言自動化或其他支援的行銷流程。
  建立或發布優惠券本身不代表授權發送訊息或發布社群內容。
- 擁有者用 `list_coupon_staff`、`set_coupon_staff`、`revoke_coupon_staff` 管理已註冊人員。
  編輯者可以編輯、發布及讀取成效；核銷人員可以檢查及核銷顧客提供的碼。
  兩種角色互不包含，不可推定編輯者也能核銷。
- 用 `get_coupon_report` 比較總量、渠道與核銷項目。核銷明細最多只有最近 25 筆，
  不可稱為完整歷史。不需登入的重複領取模式下，領取數與核銷數不等於不重複人數。
  點擊與轉換各自反映已記錄的事件，不應宣稱能證明因果關係。

## 核銷流程

使用 `inspect_coupon_redemption` 檢查顧客提供的最新核銷碼，讀取該次領取時的可核銷項目。
檢查不會消耗優惠券。只有使用者明確要求核銷、且選定回傳項目 ID 後，才能使用
`redeem_coupon`。呼叫者必須是擁有者或有權限的核銷人員。
不可替顧客建立領取紀錄、產生 QR code，或把檢查結果當成已核銷。
領取、QR code 產生及相機掃描仍由原生頁面處理。

QR code 過期或被替換時，請顧客重新顯示最新的碼；已使用的領取紀錄不能再次核銷。
結果不確定時，先用 execution ID 呼叫 `get_agent_action_status`，再判斷是否需要重試。
若用戶端支援 MCP 冪等鍵，同一操作重試應保留原本的鍵；更換鍵不代表可以安全重複核銷。
