# 讓 ChatGPT 統籌海巡大師的工作

先確認使用的社群帳號、目標、關鍵字、搜尋時間範圍、排除條件，以及使用者
希望回覆、只追蹤輿情，或兩者都要。使用者提到既有專案時，先透過
`list_projects` 與 `get_project` 讀取設定，並以 `get_automation_capabilities`
確認所選帳號支援的功能。這些工作流程的即時搜尋工具目前支援 Threads。

| 原本由 ViralArc 處理的工作 | ChatGPT 如何接手 |
| --- | --- |
| 在介面設定海巡主題 | 透過對話確認目標，沿用已儲存的專案，或直接提供搜尋條件。 |
| 由背景排程決定搜尋時間 | 依使用者要求立即執行，或在連接此外掛後，透過使用者要求建立的 ChatGPT 排程任務執行。 |
| 搜尋並篩選貼文 | 呼叫搜尋工具、閱讀實際結果，再依目標決定下一步。 |
| 在介面檢視結果與回覆草稿 | 在對話中列出原文連結、解釋挑選原因，並修改草稿。 |
| 收錄符合條件的對象 | 搜尋結果回來後，將選定結果加入客戶名單；是否收錄與是否回覆分開判斷。 |
| 彙整執行結果 | 說明找到的貼文、已收錄的客戶、草稿與發送結果，以及需要處理的事項。 |

使用者希望由 ChatGPT 接手既有專案的定期執行時，使用 `pause_topic_tracking`，
或透過 `update_topic_tracking` 設定 `automationEnabled: false`。若要建立由
ChatGPT 負責執行的新專案，建立時也設定 `automationEnabled: false`。搜尋仍可
沿用已暫停專案的設定。只設定 `automationMode: "no-comment"` 不代表移交排程；
啟用中的不留言專案仍可能由 ViralArc 的背景流程執行搜尋與客戶名單收錄。

ChatGPT 接手的是搜尋與決策流程。ViralArc 仍負責具身分驗證的搜尋、資料儲存、
發布、重複檢查與額度限制。已進入發送佇列的回覆會保留原本的排程，暫停專案
不會一併取消。先透過 `list_scheduled_replies` 檢查，只有在使用者要求取消時
才取消排程回覆。

需要定期執行時，使用已啟用排程任務與外掛存取的 ChatGPT 介面。先測試一次完整
流程，再將帳號、專案與客戶名單 ID、目標、頻率、時區、搜尋預算、回覆方式及
回報規則寫進任務指示。依 ChatGPT 的排程與授權流程設定；一般對話中的要求
本身不會建立定期執行。參閱 [ChatGPT 排程任務](https://learn.chatgpt.com/docs/automations)。

每次執行時，利用已儲存的客戶名單紀錄與回覆紀錄辨識已處理的貼文。搜尋結果
快照與操作執行紀錄會在 24 小時後到期；需長期保留的追蹤資訊，應存放於客戶
名單或排程任務支援的脈絡中，不要將舊的執行 ID 當成長期記憶。除非使用者
要求定期摘要，輿情沒有變化時不必重複通知；有新發現、重要變化、執行失敗或
需要使用者處理的事項時再回報。

## 存取權限、錯誤與操作恢復

`mcp:all` 授權開放使用者原本可用的工具，不會繞過資料所有權、方案額度、
服務提供者限制或點數。訂閱管理相關工具提供摘要與紀錄的讀取功能，不代表
有權購買或變更訂閱。CreatorOS 專用操作與管理員操作不在此 MCP 連接範圍內。

逾時或結果不明時，將該操作的 `executionId` 傳入 `get_agent_action_status`
查詢。已受理或執行中的紀錄不代表成功；失敗紀錄可用來判斷是否適合重試。
若發布結果仍不明，不得自動再發送一次。更新權杖的授權最終會到期，也可能
遭撤銷；ChatGPT 要求重新連接時，應引導使用者再次完成 OAuth 授權。
